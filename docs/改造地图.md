# 拾词输入法 · Trime 改造地图

> 基于对 `osfans/trime`（浅克隆于 `../trime-reference`）的静态分析得出。
> 结论先行：**Trime 已内置候选注释（comment）的显示机制，且已编译 librime-lua 插件**。
> 译词最省力的做法是把英文塞进候选的 comment，显示层几乎不用改。

### 一个容易踩的事实：方案文件是符号链接

`app/src/main/assets/shared/` 下的 `luna_pinyin.schema.yaml`、`default.yaml`、`essay.txt` 等
**都是符号链接**，指向子模块目录 `app/data/rime/luna-pinyin/...`、`app/data/rime/prelude/...`。
所以：

- 不执行 `git submodule update --init --recursive`，这些链接就是死链（打包后无输入法方案）；
- 想改默认方案，**不要改子模块内部**（更新子模块会被覆盖），应把自定义方案放进自己的目录，
  再拷到手机的用户数据目录。详见 [`编译与调试.md`](编译与调试.md)。

## 二、三条译词实现路线

### 路线 A（MVP 首选，改动最小）：词典第三列即注释

- **原理**：Rime 词典行格式为 `词<TAB>编码<TAB>第三列`；第三列**非纯数字**时即作为该候选的
  comment，Trime 显示层自动渲染在候选旁。
- **做法**：
  1. 用 `tools/cedict_to_rime.py` 把 CC-CEDICT 与 `luna_pinyin.dict.yaml` 合并成
     `pickword_en.dict.yaml`（词 / 拼音 / 英文注释）。
  2. 用 `rime/pickword.schema.yaml`（本仓库已备模板）作方案，`translator.dictionary: pickword_en`。
  3. 语言切换（英 / 日 / 西）= 换一套 dictionary；关闭译词 = 换回原 luna_pinyin 或留空第三列。
- **优点**：Android 代码零改动，纯离线，词典可独立迭代。
- **缺点**：覆盖不到的词没有注释；多音字/词组需要词典侧处理。

### 路线 A2（覆盖面补强）：Lua filter 注入注释

- **前提已满足**：`RIME_PLUGINS` 含 `librime-lua`，且 `rime_jni.cc` 已注册，无需改 JNI。
- **做法**：
  1. `python tools/cedict_to_rime.py --format lua --out rime/lua/pickword_gloss.lua`
     生成 Lua 词表；
  2. 部署 `rime/lua/pickword_comment.lua`（本仓库已备）到用户数据目录的 `lua/`；
  3. 方案 `engine/filters` 加 `- lua_filter@*pickword_comment@pw_gloss`；
  4. 用 switch `show_gloss` 控制开/关，关闭时 filter 直接透传（零开销）。
- **优点**：不改词典即可补注释、可动态开关、可做格式裁剪（词性/长度）。
- **缺点**：需实测 `require` 在 Android 上的可用性（脚本已内置 `dofile` 兜底）。

### 路线 B（产品化，控制力最强）：Android 层后处理

- **原理**：在 `CandidatesPagingSource.load()` 拿到 `Array<CandidateProto>` 后，逐条查本地译词库
  （由 `cedict_to_rime.py --sqlite` 生成的 SQLite），把 `comment` 改写为译词。
- **做法**：
  1. `RimeProto.kt` 的 `comment` 改为 `var`（或新建 DTO）以便后写；当前是 `val`（不可变），需调整。
  2. 在 `CandidatesPagingSource.load()` 拿到 candidates 后 `map { it.copy(comment = lookup(it.text)) }`。
  3. 译词库：SQLite/Room；语言与开关由 App 设置控制。
- **优点**：翻译逻辑、语言切换、格式、开关全在 App 内，易迭代；可与生词本共用数据源。
- **缺点**：需改数据模型 + 加 DB + 改装配点，工作量大于 A/A2。

> **建议**：路线 A 打底（出第一个"候选旁有英文"的包），A2 补覆盖与开关；
> 等要做生词本 / 多语言 / 词表管理时，再统一迁到路线 B。

## 三、词汇资产生成（一条命令）

```bash
# 路线 A：带英文注释的 Rime 词典
python tools/cedict_to_rime.py \
  --cedict ~/Downloads/cedict_ts.u8 \
  --rime-dict ../app/data/rime/luna-pinyin/luna_pinyin.dict.yaml \
  --out rime/dicts/pickword_en.dict.yaml

# 路线 A2 / B：同一份数据的另两种形态
python tools/cedict_to_rime.py ... --format lua   --out rime/lua/pickword_gloss.lua
python tools/cedict_to_rime.py ... --sqlite rime/dicts/pickword_en.db
```

输入、参数、部署位置与验证清单见 [`rime/dicts/README.md`](../rime/dicts/README.md)。

## 四、P2 学习闭环（全新 Android 层）

- **生词本**：Room 数据库（实体：词、释义、熟练度、下次复习时间、创建时间），与译词库可共用或独立。
- **收藏入口**：长按候选 → 在 `CandidateItemUi` / 弹窗候选增加菜单或按钮 → 写入 Room。
- **复习**：新建 `ui/main/` 下的 Activity / Fragment，实现 SM-2 间隔重复调度 + 学习趋势图。
- **词表导入**：解析四六级 / 雅思等 CSV 写入 Room。

## 五、设置与开关

- 在 `ui/main/settings/` 新增 `PickWordSettingsFragment`：语言选择（英 / 日 / 西）、译词开关、生词本入口。
- 开关写入 `trime.yaml` 或 App 私有配置；路线 A/A2 走 Rime 的 `switches`（如 `show_gloss`），
  由 Trime 的热重载/重新部署生效。

## 六、构建与上架

- **环境**：Android Studio + SDK + NDK；仓库已含 librime 源码（子模块），首次构建会全量编译 C++。
- **命令**：`./gradlew assembleDebug`（本地调试）；上架用 `assembleRelease`（需配签名）。
- **合规**：fork 后 LICENSE 保持 GPL-3.0；不沿用"Trime / 青简 / 水杉"等他人品牌；App 名与软著名一致。

## 七、推荐起步顺序

1. clone Trime（**带子模块**）跑通 debug 包 → 收尾 P0（见[`编译与调试.md`](编译与调试.md)）。
2. 生成 `pickword_en.dict.yaml`，用**路线 A**跑通最小译词 → 出第一个"候选旁有英文"的包 → 酷安内测。
3. 加**路线 A2**（Lua filter + `show_gloss` 开关）补齐覆盖与开关。
4. 视反馈决定是否迁**路线 B**，再做语言切换 / 生词本 / 词表导入（P2）。
