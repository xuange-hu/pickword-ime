# 拾词输入法 · 产品架构（v0.1）

> 本文说明「成品 APK 为什么这样设计」，覆盖构思、架构、数据、兼容性与便利性。
> 与 [`改造地图.md`](改造地图.md) 的区别：那是「基于 Trime 的改造路线」，本文是
> **当前可运行版本（自研内核，无 NDK 依赖）** 的实现说明。二者共用同一套词库数据格式。

## 一、产品构思

一句话：**把「打字」这个每天几百次的动作，变成外语词汇的输入与复现。**

闭环由三段组成，缺一不可：

1. **见**：候选词旁常驻英文译词（不点开、不打断输入）。
2. **收**：看到想记的词，点候选右侧的 ☆，一秒进入生词本。
3. **复**：生词本按 SM-2 间隔重复调度，到点提醒复习。

关键取舍：**不做「强制背单词」**。输入法的主业是打字，学习必须是零成本的副产品。
因此译词默认开启但可一键关闭，复习入口不打扰输入。

## 二、分层架构

```
┌──────────────────────────────────────────────────────┐
│  表现层  ui/                                          │
│  MainActivity（启用向导/试打）  SettingsActivity       │
│  WordBookActivity（生词本）     ReviewActivity（复习）  │
├──────────────────────────────────────────────────────┤
│  输入法层  ime/                                       │
│  PickWordImeService（InputMethodService）             │
│   · 键盘事件 → 拼音串 → 候选 → 上屏                    │
│   · 候选条渲染（词 + 英文 + ☆）                        │
│   · 中/英切换、符号层、触感反馈                         │
├──────────────────────────────────────────────────────┤
│  引擎层  engine/                                      │
│  SyllableSplitter（动态规划音节切分）                  │
│  PinyinEngine（五级匹配 + 整句组合 + 词频排序）         │
│  Candidate（候选模型）                                 │
├──────────────────────────────────────────────────────┤
│  数据层  data/ · vocab/                               │
│  Dictionary（assets 词库，只读）                       │
│  Store（user.db：用户词频 + 生词本）                    │
│  SrsScheduler（SM-2）  WordListIo（CSV/JSON 导入导出） │
└──────────────────────────────────────────────────────┘
```

依赖方向单向向下：`ui → ime → engine → data`，引擎不感知 Android 视图，便于单测与迁移。

## 三、输入引擎

### 3.1 音节切分

用户输入的是一串无空格字母（`woshi`）。`SyllableSplitter` 用动态规划枚举所有合法音节切分，
并只保留「音节数最少」的若干方案（上限 8 个），避免组合爆炸。音节表内置 410 个普通话无调音节。

### 3.2 五级匹配与打分

| 优先级 | 匹配方式 | 基础分 | 说明 |
|---|---|---|---|
| 1 | 整词全拼 `raw = 输入` | 1200 | `diannao → 电脑` |
| 2 | 切分后词组 `pinyin = "wo shi"` | 1000 | 多音节词组 |
| 3 | 首音节单字 | 950 | 边打边出字 |
| 4 | 整句组合 | 1080 | 无词条时用高频单字拼短语（`woshi → 我是`） |
| 5 | 前缀 `raw LIKE 'woshi%'` | 700 | 范围查询走索引，边打边出词 |
| 6 | 简拼 `initials = "ws"` | 500 | 首字母速记 |

最终得分 = 基础分 + 词频加成（0–100）− 前缀长度惩罚。同分时短词优先。

### 3.3 词频

词频来自 **jieba 现代汉语词频表**（34.9 万词），对数归一化到 0–1000；
未命中的词用 Rime 单字顺序兜底；古文语料只作补充且上限压低，避免「血洗」压过「学习」。
用户上屏行为再叠加 0–300 的个人加权，越用越顺手。

## 四、数据设计

两条独立链路，互不污染：

| 库 | 位置 | 内容 | 可写 |
|---|---|---|---|
| `pickword.db` | APK assets → 首次启动复制到私有目录 | 14.5 万词条：词 / 拼音 / 简拼 / 词频 / 英文 | 否（只读） |
| `user.db` | 应用私有目录 | 用户词频、生词本（含 SM-2 字段） | 是 |

生词本字段：`ease`（熟练系数）、`interval_days`、`due`、`reps`、`lapses`，
按 SM-2 更新：认识 → 间隔 1→6→interval×ease；忘记 → 重置为 1 天并累计 lapses。

## 五、兼容性

| 维度 | 策略 |
|---|---|
| 系统版本 | `minSdk 21`（Android 5.0）→ `targetSdk 36`（Android 16），单套代码 |
| 深色模式 | `values-night` 资源自动切换，无需代码分支 |
| ABI | 纯 Java，无 native 库，天然支持 64 位与全架构 |
| 权限 | 仅 `VIBRATE`；**不申请 INTERNET**，飞行模式下功能完整 |
| 旧版 SQLite | 不使用 UPSERT 等新语法，Android 5 可用 |
| 键盘高度 | 矮/标准/高 三档，适配小屏与平板 |
| 密码框 | 自动切英文并关闭联想，避免拼音串进入密码 |
| 横竖屏 | 固定行高按 dp 计算，不依赖固定像素 |

## 六、便利性

- **启用向导**：主界面两步按钮（去启用 → 切换当前输入法），并实时显示状态。
- **试打区**：不离开应用即可验证键盘与译词效果。
- **一键收藏**：候选右侧 ☆，Toast 即时反馈，不打断输入。
- **词表导入**：支持 CSV（`词,释义` 或 Tab 分隔），可直接导入四六级/雅思词表。
- **备份导出**：生词本导出 JSON（含复习进度），换机可迁移。
- **设置粒度**：译词开关 / 译词位置 / 按键振动 / 主题 / 键盘高度 / 清除词频。
- **零配置**：装完即用，词库随包内置，无需下载语言包。

## 七、生态与许可

| 数据 | 来源 | 许可 |
|---|---|---|
| 汉英释义 | CC-CEDICT | CC BY-SA 3.0 |
| 拼音与单字 | Rime 明月拼音（rime-luna-pinyin） | GPL-3.0 / 词典数据开放 |
| 现代词频 | jieba dict.txt | MIT |
| 代码 | 本项目 | GPL-3.0 |

可扩展方向：更多语种词典（日/西）只需替换 `gloss` 列与增加对应词条；
Lua/Rime 方案（见改造地图）可复用同一份数据，形成「自研内核」与「Trime 内核」双实现。

## 八、路线

- **v0.1（当前）**：拼音输入 + 候选译词 + 收藏 + SM-2 复习 + 词表导入导出。
- **v0.2**：候选长按菜单、用户自造词、词性标注、复习提醒通知。
- **v1.0**：多语种、云同步（可选）、酷安/OPPO/vivo 上架资料齐备。

## 九、已知限制

- 无语言模型，长句组合是「每音节取最优单字」，不是全局最优，个别句子需要手动选词。
- 词库以简体为主，繁体词条少量混入（取自 CEDICT 的 simp 字段）。
- 复习提醒需应用在前台或手动进入；后台通知在 v0.2 补齐。
- APK 未使用正式签名（当前 release 复用 debug 签名），上架前需替换。
