# 编译与调试

本文件分两部分：

- **第一部分**：构建本仓库自研的拾词输入法（v0.1，无 NDK，几分钟出包）——日常开发看这里。
- **第二部分（附录）**：如果你要走同文 Trime 路线（Rime 生态、多方案），按附录操作。
  基线来自对 `osfans/trime` 的静态分析：`compileSdk=37` / `buildToolsVersion=36.0.0`
  / `minSdk=21` / `targetSdk=37` / `versionName=3.3.13` / Gradle `9.7.1`。

# 第一部分 · 构建拾词输入法（自研内核）

## 1. 环境

| 项 | 版本/要求 | 说明 |
|---|---|---|
| JDK | **17** | AGP 8.7.3 的官方支持版本；JDK 21/25 可能报 class 版本错误 |
| Android SDK | Platform **36**、Build Tools **36.0.0**、Platform Tools | 无需 NDK |
| Gradle | **8.13** | 可用 wrapper 或本机安装 |
| 磁盘 | 约 2 GB | 依赖 + 构建缓存 |
| 网络 | 首次构建需联网 | 首次拉 AGP 与 AndroidX，之后可离线 |

`local.properties` 里写 SDK 路径（不要提交到仓库）：

```properties
sdk.dir=C\:\\Users\\<you>\\AppData\\Local\\Android\\Sdk
```

## 2. 构建

```bash
# 词库已随仓库提供（app/src/main/assets/pickword.db，约 15 MB）
# 只有改了词源才需要重跑：
python tools/build_ime_db.py --luna luna_pinyin.dict.yaml --cedict cccedict.txt \
       --freq-dict jieba_dict.txt --out app/src/main/assets/pickword.db

# Debug 包（可直接装）
./gradlew :app:assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# Release 包（当前配置复用 debug 签名，见下方“签名”）
./gradlew :app:assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

## 3. 安装与启用

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

手机上：设置 → 系统 → 语言和输入法 → 启用「拾词输入法」→ 切换为当前输入法。
打开 App 首页有「启用 / 切换」两个按钮和试打区，可自查状态。

## 4. 签名（上架前必做）

当前 `release` 构建复用 debug 签名，只适合内测分发。正式上架请生成自己的 keystore：

```bash
keytool -genkeypair -v -keystore pickword-release.jks -alias pickword \
        -keyalg RSA -keysize 2048 -validity 10000
```

然后在 `app/build.gradle` 里新增 `signingConfigs.release` 并把 `buildTypes.release` 指向它；
`*.jks` 已在 `.gitignore` 中，**密钥与口令不要提交**。换签名后旧包无法覆盖安装，需先卸载。

## 5. 常见问题（自研内核）

| 现象 | 原因 / 处理 |
|---|---|
| `Duplicate class kotlin.collections.jdk8...` | AppCompat 带入旧 kotlin-stdlib-jdk7/8；项目已用 `configurations.configureEach { exclude ... }` 排除 |
| `attribute android:allCaps not found` | 该 attr 在当前平台包不可用；不要用 `android:allCaps`，用中文文案规避大小写 |
| `resource attr/123 not found` | 字符串值以 `?` 开头会被当成属性引用；避免 `?123` 这类文案 |
| `BuildConfig` 找不到 | AGP 8 默认关闭；`buildFeatures { buildConfig = true }` |
| 首次弹出键盘候选为空 | 词库正在复制（约 15 MB），一两秒后自动就绪；可先在 App 首页停留片刻 |
| 装了但输入法列表没有 | 确认 `AndroidManifest` 中 service 的 `BIND_INPUT_METHOD` 权限与 `android.view.im` meta-data 未被改动 |

# 第二部分（附录）· 走 Trime 路线

## 一、环境准备

| 项 | 要求 |
|---|---|
| Android Studio | 较新版本（能装 SDK Platform 37 与 Build Tools 36.0.0 的版本） |
| SDK | Android SDK Platform 37、Build Tools 36.0.0 |
| NDK | 通过 SDK Manager 安装 **NDK (Side by side)** 与 **CMake** |
| JDK | Android Studio 自带即可 |
| 磁盘 | 建议预留 **20 GB**：子模块 + NDK + 构建缓存 |
| 网络 | 首次构建要拉 Gradle 依赖与 C++ 依赖，必须联网 |

## 二、拉代码（关键：必须带子模块）

```bash
git clone https://github.com/osfans/trime.git app
cd app
git submodule update --init --recursive
```

**为什么必须拉子模块**：`app/src/main/assets/shared/` 下的 `luna_pinyin.schema.yaml`、
`default.yaml`、`essay.txt` 等都是**符号链接**，指向子模块目录
`app/data/rime/luna-pinyin/...`。子模块没拉时这些链接是死链，表现为"打包无输入法方案"或
构建期找不到文件。

子模块清单（`.gitmodules`）：OpenCC、snappy、librime、librime-lua、librime-lua-deps、
librime-octagram、librime-predict、prelude、luna-pinyin、stroke、essay。

Windows 额外注意：符号链接需要
```bash
git config --global core.symlinks true
```
并且 clone/checkout 时以**管理员权限**运行，否则 Git 会把符号链接落成普通文本文件
（内容是一串 `../../../../data/rime/...`），方案照样加载不了。发现这种情况：
开管理员终端执行 `git checkout -- .` 或 `git rm --cached -r app/src/main/assets/shared && git reset --hard`。

## 三、构建

```bash
# 调试包（Windows 用 gradlew.bat）
./gradlew assembleDebug          # 只出 APK
./gradlew installDebug           # 直接装到已连接的设备/模拟器

# 发布包：需先配签名（见下），再
./gradlew assembleRelease
```

产物默认在 `app/build/outputs/apk/<variant>/`。

**首次构建耗时较长**：CMake 会编译 librime 及其依赖（glog、yaml-cpp、leveldb、marisa-trie、
OpenCC、snappy）与插件（librime-lua、librime-octagram、librime-predict），
`app/src/main/jni/cmake/Rime.cmake` 中 `RIME_PLUGINS` 已包含 **librime-lua**，
且 `librime_jni/rime_jni.cc` 里已调用 `rime_require_module_lua()`——
**即 Lua 脚本插件开箱可用**，这正是路线 A2 的基础。

## 四、改成自己的 App（P1 必做）

| 位置 | 改什么 |
|---|---|
| `app/build.gradle.kts` | `namespace` 与 `applicationId` → 如 `com.xuangehu.pickword`（第 20、25 行） |
| `app/src/main/res/values/strings.xml` | `app_name` → 与软著名一致（**定稿后不可改**） |
| 图标 | 替换 `res/mipmap-*`，不要用他人品牌图形 |
| LICENSE | 保留 GPL-3.0（Trime 本身 GPL-3.0-or-later，继承义务） |
| 权限 | 默认不申请 `INTERNET`；不得新增任何上报/统计 SDK |

> 改 `applicationId` 会改变 App 的用户数据目录，手机上旧数据不会迁移，属正常现象。

## 五、assets 改动与数据校验

Trime 用自定义 Gradle 插件 `com.osfans.trime.data-checksums`
（`build-logic/convention/.../DataChecksumsPlugin.kt`）为 `assets/` 生成
`checksums.json`，App 端据此判断是否需要重新部署内置数据。

因此你**新增/修改了 `assets/` 下的方案或词典**时：
- 构建会自动跑 `generateDataChecksums`，不要手工编辑 `checksums.json`；
- 若遇到"改了方案但手机没生效"，执行 `./gradlew cleanDatacheksums`（注意官方拼写）
  再重新构建/安装。

改子模块内的文件（如 `app/data/rime/luna-pinyin/*`）**不要提交**，更新子模块会被覆盖；
自定义方案一律放你自己的目录（`rime/`）再拷进用户数据目录。

## 六、调试 Rime 方案（不动 Android 代码）

1. 手机装好 Trime/拾词包 → 启用输入法 → 进入「用户数据目录」（通常在
   `/storage/emulated/0/Android/data/<包名>/files/rime`）。
2. 拷入 `rime/pickword.schema.yaml` 与生成好的词典。
3. App 内点「部署 / 重新部署」；Trime 支持热重载，不用重装 APK。
4. 看日志：`adb logcat | grep -i rime`。
5. 观察候选旁是否出现英文注释；若注释挤爆候选条，调小 `--max-gloss` 或主题里的
   `comment_text_size` / `comment_position`。

## 七、常见坑速查

| 现象 | 原因 / 处理 |
|---|---|
| `fatal: not a git repository` | 在错误目录执行命令，先 `cd` 进项目根目录 |
| 打包后没有拼音方案 | 子模块没拉 / 符号链接失效 |
| 首次构建卡很久 | 正常，C++ 全量编译；之后增量很快 |
| CMake 报错找不到 Boost/Glog | 依赖没拉全，重跑 `git submodule update --init --recursive` |
| 改了方案不生效 | 清 `checksums.json` 或重新部署；确认方案文件在用户数据目录 |
| 手机上候选无注释 | 词典第三列没生效 → 换 Lua filter（路线 A2）或检查 prism 是否重新编译 |
| 编译 Android 代码报错但 native 正常 | 先 `./gradlew --stop` 再 Sync Gradle |
